# CSV Launcher 要件定義書

## 1. 文書の目的

本書は CSV Launcher の開発目的、機能要件、非機能要件、運用要件を定義する。
実装詳細（クラス構成、アルゴリズム、具体的な API 呼び出し）は対象外とし、別紙「詳細仕様書」で扱う。

## 2. 背景

Windows 環境で CSV ファイルを開く際、Excel やテキストエディタではなく Google スプレッドシートを既定の作業先にしたい。
ユーザーの操作を増やさず、CSV のダブルクリックのみでクラウド上で閲覧・編集できる体験を提供する。

## 3. システム概要

CSV Launcher は Windows のファイル関連付けで起動される CLI アプリケーションである。
入力された CSV ファイルを Google Drive にアップロードして Google スプレッドシートとして開く。
CSV パス未指定で起動された場合は、空の Google スプレッドシートを新規作成して開く。

## 4. スコープ

### 4.1 対象
- Windows 10/11 の現在ユーザー環境
- .csv ファイルの既定アプリ連携
- Google OAuth 2.0 認証を用いた Google Drive 連携
- Google スプレッドシートとしての表示

### 4.2 対象外
- macOS / Linux の関連付け
- CSV 内容の変換・加工・整形
- スプレッドシート上の編集自動化
- Drive 上ファイルの削除 UI 提供

## 5. 利用者像

- 日常的に CSV を扱う個人ユーザー
- Google アカウントでクラウド編集を行うユーザー

## 6. ユースケース

### UC-01: CSV をダブルクリックして開く
1. ユーザーが .csv をダブルクリックする。
2. CSV Launcher が起動し、CSV を Google Drive にアップロードする。
3. アップロードされた Google スプレッドシートが既定ブラウザで開く。

### UC-02: 初回認証
1. 未認証状態で CSV Launcher を起動する。
2. ブラウザで OAuth 認証画面が表示される。
3. 認証完了後、以降は再認証なしで利用できる（トークン有効期間内）。

### UC-03: 同名ファイル時の動作制御
1. 同名のスプレッドシートが既に存在する状態で起動する。
2. 既存ファイルは保持され、新規スプレッドシートが作成される。

### UC-04: 引数なし起動
1. ユーザーが CSV パス指定なしで CSV Launcher を起動する。
2. CSV Launcher が空の Google スプレッドシートを新規作成する。
3. 作成されたスプレッドシートが既定ブラウザで開く。

## 7. 機能要件

### FR-01: 起動と入力
- CSV ファイルパスをコマンドライン引数として受け取れること。
- CSV パスは省略可能であること。
- CSV パス指定時に、複数指定または不正なパスの場合は異常終了すること。

### FR-02: 認証
- Google OAuth 2.0 によりユーザー認証できること。
- 認証後トークンを保存し、再起動後も再利用できること。

### FR-03: アップロード
- Google Drive API により CSV をアップロードできること。
- アップロード時に Google スプレッドシート形式へ変換されること。
- 任意でアップロード先フォルダを指定できること。

### FR-03A: 空スプレッドシート作成
- CSV パス未指定時、空の Google スプレッドシートを新規作成できること。
- 任意で作成先フォルダを指定できること。

### FR-04: 重複ファイル制御
- 同名ファイル存在時も既存ファイルを保持し、新規スプレッドシートを作成すること。

### FR-05: ブラウザ表示
- アップロード成功時に対象スプレッドシートを既定ブラウザで開くこと。

### FR-06: ファイル関連付け
- PowerShell スクリプトで .csv 関連付けを登録/解除できること。
- 登録先は現在ユーザーのレジストリ領域であること。

### FR-07: 文字コード対応
- UTF-8 および Shift-JIS 系 CSV を取り込めること。
- 文字化けを低減するため、文字コード判定を行うこと。

## 8. 非機能要件

### NFR-01: 対応環境
- OS は Windows 10/11 を対象とする。
- 配布物は単体実行可能な EXE とする。

### NFR-02: 操作性
- 認証済み環境では、CSV ダブルクリック後すみやかにアップロード処理へ進むこと。

### NFR-03: エラー通知
- エラー内容は標準エラー出力へ表示すること。
- 正常/異常を終了コードで判別できること。

### NFR-04: セキュリティ
- OAuth クライアント情報とユーザートークンは適切に分離管理すること。
- トークン保存先はユーザー領域とすること。

## 9. 外部インターフェース要件

### 9.1 CLI
- オプション引数でフォルダ指定を受け付けること。
- ヘルプ表示引数を提供すること。
- CSV パス省略時の動作（空スプレッドシート作成）を提供すること。

### 9.2 Google API
- Google Drive API v3 を利用すること。
- OAuth スコープは drive.file 相当を利用すること。

### 9.3 OS 連携
- レジストリによる .csv 関連付けを行うこと。
- 既定ブラウザ起動で URL を開くこと。

## 10. 運用要件

- ビルド時に OAuth クライアント情報をアプリへ取り込めること。
- 配布時に関連付け用スクリプトを同梱すること。
- 関連付け解除手段を提供すること。

## 11. 受け入れ条件

1. CSV ダブルクリックで Google スプレッドシートが開くこと。
2. 未認証時に OAuth 認証へ遷移し、認証後に処理継続できること。
3. 同名ファイル存在時も既存ファイルが保持され、新規作成されること。
4. エラー時は非 0 終了コードで終了し、標準エラーに理由が出ること。
5. setup スクリプトで関連付け登録と解除ができること。
6. CSV パスなし起動時に、空の Google スプレッドシートが作成・表示されること。
